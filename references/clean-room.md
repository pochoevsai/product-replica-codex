# Clean-room and release guardrails

This reference applies whenever another product is used as research input.

## Allowed working material

- public product pages, help pages, documentation, public screenshots, public store listings, and public reviews;
- behavior observed through the user's own account or a test account the user is authorized to use;
- requirements and assets supplied by the user or created independently.

## Do not do

- bypass authentication, a paywall, anti-bot controls, robots restrictions, rate limits, or a site's technical access controls;
- scrape private data or another person's account;
- copy source code, proprietary assets, text, database contents, user-generated content, catalogue/media, logos, trademarks, or private API behavior;
- reuse credentials, tokens, cookies, API keys, or production data;
- imply affiliation, endorsement, compatibility, or ownership without evidence and permission;
- publish or deploy merely because an automated check passed.

## Before commercial release

Check:

- name, domain, logo, icon, visual identity, and copy are distinct and reviewed for trademark/confusion risk;
- every dependency, font, icon, image, dataset, and API has a compatible license and allowed usage;
- privacy notice, consent, retention, deletion, export, and access controls match the data collected;
- payments, subscriptions, taxes, refunds, app-store rules, and third-party terms are addressed;
- production secrets, backups, monitoring, error reporting, rollback, and incident contacts are ready;
- a qualified lawyer reviews material uncertainty when money, regulated data, or a likely competitor relationship is involved.

The skill can identify risks and prepare a checklist; it cannot provide legal clearance.
